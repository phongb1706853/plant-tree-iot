Giới thiệu

Plant Tree IoT là hệ thống quản lý vườn cây thông minh dùng ESP32 + .NET + MongoDB. Thiết bị (ESP32) gửi telemetry lên server qua MQTT. Ở chế độ auto, server tự quyết định tưới và bật/tắt đèn theo ngưỡng của từng thiết bị; server cũng nhận lệnh thủ công từ App (bơm, đèn, chế độ, tin nhắn) rồi gửi xuống ESP32 qua MQTT.

Người làm App: bắt đầu ở tab Bắt đầu cho App.

Vì sao MCP không cần expose ra ngoài

MCP protocol mặc định dùng stdio — Ollama UI spawn MCP server làm subprocess, giao tiếp qua stdin/stdout. MCP server bên trong gọi REST API qua HTTPS tunnel. Đây là cách chuẩn MCP, không cần expose port riêng cho MCP.

Chức năng

Devices

  • Đăng ký thiết bị mới với metadata (tên cây, vị trí, plant type)
  • Heartbeat tracking — server biết device nào online
  • List, search device

Sensor Data

  • Upload telemetry (nhiệt độ, độ ẩm, độ ẩm đất %, ánh sáng, áp suất, độ cao, pin, chế độ, trạng thái bơm/đèn, cờ cảnh báo)
  • Payload snake_case đúng hợp đồng (device_id, temperature_c, soil_percent…) — giống hệt telemetry thiết bị publish lên xmini/sensor_data
  • Lấy sensor mới nhất, history, theo khoảng thời gian

Chế độ auto (thiết bị thật tự làm — firmware 2.1.0)

  • Thiết bị tự tưới theo liều (dose-and-soak: soil_on_pct / soil_off_pct, pump_dose_ms, soak_s, hạn mức liều) và tự bật đèn (chỉ khi light_auto=true, theo lux_on / lux_off). Server không gửi lệnh auto cho thiết bị thật
  • Muốn đổi hành vi auto → chỉnh cấu hình (25 khoá): GET/PUT /api/control/{deviceId}/config
  • Thiết bị publish cấu hình hiện tại lên xmini/config (retained) khi nối lần đầu và sau mỗi lệnh config; khoá sai bị từ chối và báo trong rejected
  • Thiết bị ảo SIM_* giữ luật cũ: server tự tưới / tự bật đèn

Control

  • Gửi lệnh thủ công: bơm {"pump":true} (= đúng 1 liều), đèn {"light":true}, PWM đèn {"light_pwm":180}. Các lệnh này đưa thiết bị về MANUAL — gọi /auto để trả lại
  • Đổi chế độ {"mode":"auto"|"manual"}, màn hình TFT {"message":"...","message_secs":N} (server tự bỏ dấu), hiện QR cài đặt {"show_qr":true}
  • Server publish khoá phẳng xuống xmini/control với QoS 1 và id duy nhất; xem nhật ký lệnh qua GET /api/control/commands/{deviceId}
  • Trạng thái kết nối (online / sleeping / late / offline) từ topic xmini/status: GET /api/devices/{deviceId}/status

Quyền: owner và member

Mỗi device có 1 owner (người đăng ký device) và danh sách members (được owner chia sẻ). GET /api/devices trả cả device mình sở hữu lẫn device được chia sẻ.

Thao tácOwnerMember
Xem device, số đo, ngưỡng, nhật ký lệnh, danh sách thành viên✅✅
Điều khiển (tưới, đèn, chế độ, tin nhắn) và đổi ngưỡng✅✅

Để biết user hiện tại có phải owner: so device.ownerId với claim nameid (userId) trong JWT, hoặc so owner.email của GET /api/devices/{deviceId}/members với email đăng nhập. GET /api/auth/me không trả userId. Member chưa tự rời device được, chỉ owner thu hồi.

Chế độ auto / manual

  • Thiết bị làm chủ chế độ (firmware 2.1.0). Trường mode của số đo mới nhất (GET /api/sensordata/latest/{deviceId}) là sự thật; server chép nó vào controlMode của device (null = "auto"). GET /api/devices/{deviceId}/status cũng trả mode.
  • Auto: thiết bị tự tưới theo liều (mở đợt khi đất < soil_on_pct, mỗi liều pump_dose_ms, chờ soak_s, tối đa max_doses_per_cycle / đợt và max_doses_per_day / 24 h, đóng khi đất ≥ soil_off_pct) và tự bật đèn chỉ khi light_auto=true. Tự tưới bị chặn khi soilOk=false, soilFault=true hoặc safeMode=true.
  • Mọi lệnh tưới / đèn từ App đưa thiết bị về MANUAL (kể cả khi lệnh bơm bị bỏ qua). Ở MANUAL thiết bị không tự làm gì và không có gì tự tắt đèn. App nên hiện rõ chế độ manual và có nút "Trả về tự động" (POST /api/control/{deviceId}/auto). Reboot cũng đưa thiết bị về auto.
  • Response lệnh có expectedMode = chế độ thiết bị sẽ ở sau lệnh, để App cập nhật ngay.
  • Lệnh trả 200 nghĩa là server đã gửi lệnh (QoS 1, broker đã nhận), chưa chắc thiết bị đã làm. Không có ACK. Xác nhận bằng số đo kế tiếp: bơm → dosesToday tăng; đèn → lightOn, lightPwm; chế độ → mode.

Online / offline

Dùng GET /api/devices/{deviceId}/status: trường connection = online (nghe thấy ≤ 90 s), late (im lặng > 90 s), offline (thiết bị rớt mạng — broker báo LWT — hoặc im lặng > 240 s), sleeping (chỉ bản pin), unknown (chưa nghe gì). Bản hiện tại chạy adapter nên luôn thức, số đo 10 giây/lần. Đừng dùng isActive (luôn true).

Luồng màn hình gợi ý

  1. Đăng nhập / đăng ký: POST /api/auth/login hoặc /api/auth/register, lưu token. Khi mở lại App, gọi GET /api/auth/me; nếu 401 thì về màn đăng nhập.
  2. Danh sách cây: GET /api/devices.
  3. Thêm cây: POST /api/devices/register với deviceId của thiết bị.
  4. Chi tiết cây: GET /api/devices/{deviceId}/status (online, chế độ) và GET /api/sensordata/latest/{deviceId}. Khi màn hình đang mở, gọi lại latest mỗi ~10 giây.
  5. Biểu đồ: GET /api/sensordata/history/{deviceId}?limit=N.
  6. Điều khiển: /water (1 liều), /light, /auto (trả về tự động), /show-qr (hiện QR cài đặt WiFi).
  7. Cài đặt: GET và PUT /api/control/{deviceId}/config (25 khoá; đọc rejected sau khi lưu).
  8. Chia sẻ: share, members, thu hồi bằng DELETE /api/devices/{deviceId}/share/{memberId}.
  9. Trợ lý AI: POST /api/assistant/v1/chat/completions.

Lấy token

# bash/zsh (cần jq)
export TOKEN=$(curl -s -X POST $API/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"your-password"}' | jq -r .token)
# PowerShell
$TOKEN = (Invoke-RestMethod -Method Post "$API/api/auth/login" -ContentType "application/json" `
  -Body '{"email":"you@example.com","password":"your-password"}').token
Ví dụ curl ở các tab sau viết theo cú pháp bash/zsh. Trên PowerShell 5.1 dùng curl.exe (không phải curl) hoặc Invoke-RestMethod.

Control — Điều khiển

Server gửi lệnh xuống thiết bị qua MQTT (xmini/control, QoS 1, kèm id duy nhất) ngay khi nhận request. App nên dùng các endpoint gọn /water, /light, /auto, /show-qr. Endpoint tổng quát POST /api/control/{deviceId} dùng để hiện tin nhắn trên màn hình thiết bị, chuyển manual, hoặc gộp nhiều lệnh. Mọi endpoint cần Authorization: Bearer $TOKEN.

Lệnh tưới / đèn đưa thiết bị về MANUAL. Ở manual thiết bị không tự tưới, không tự bật/tắt đèn, cho tới khi App gọi /auto (hoặc thiết bị reboot). App nên hiện rõ chế độ và có nút "Trả về tự động". Chi tiết ở tab Bắt đầu cho App, mục "Chế độ auto / manual".

Response chung của mọi lệnh

HTTP 200
{
  "message": "Đã gửi lệnh xuống xmini/control",
  "deviceId": "ESP32S3_Zone1",
  "commandId": "c-1762925000123-7",
  "expectedMode": "manual",
  "published": { "id": "c-1762925000123-7", "pump": true }
}

published là đúng payload đã gửi xuống thiết bị. commandId = id chống giao lặp (server tự sinh, id App gửi bị bỏ qua). expectedMode = chế độ thiết bị sẽ ở sau lệnh. Lỗi chung: 404 khi device không tồn tại hoặc không có quyền; 503 MQTT publisher chưa kết nối broker — không gửi được lệnh.

Không có ACK từ thiết bị. Xác nhận bằng số đo kế tiếp (~10 s): tưới → dosesToday tăng; đèn → lightOn / lightPwm; chế độ → mode.
POST /api/control/{deviceId}/water

{"on":true} = tưới đúng 1 liều (pump_dose_ms, mặc định 2 giây) rồi bơm tự tắt. {"on":false} = dừng liều đang chạy. Bắt buộc có body; gửi {} sẽ bị hiểu là dừng. Liều bị bỏ qua nếu liều trước chưa xong + 3 giây (vẫn chuyển manual).

curl -X POST $API/api/control/$DEVICE/water \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"on":true}'
published · expectedMode
{ "id": "c-1762925000123-7", "pump": true }      expectedMode: "manual"
POST /api/control/{deviceId}/light

Trợ lý AI — Chat API

Người dùng chat bằng ngôn ngữ tự nhiên: hỏi tình trạng cây, xin lời khuyên, hoặc ra lệnh ("tưới cây Zone 1"). Endpoint theo chuẩn OpenAI Chat Completions. Muốn dùng thư viện OpenAI có sẵn: đặt base URL = $API/api/assistant/v1 và API key = JWT của người dùng (thư viện tự gửi Authorization: Bearer).

POST /api/assistant/v1/chat/completions
  • Server không lưu hội thoại. App giữ toàn bộ messages[], thêm câu trả lời của trợ lý vào mảng, và gửi lại cả mảng ở mỗi lượt.
  • Server tự gán người dùng theo token (App không cần gửi user), luôn tắt streaming (stream bị ép false), và dùng model mặc định plant-assistant nếu App không gửi.
  • Trả lời có thể mất vài chục giây (server chờ AI tối đa 120 giây), nên đặt timeout request của App ≥ 120 giây.
curl -X POST $API/api/assistant/v1/chat/completions \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Độ ẩm đất của ESP32S3_Zone1 bao nhiêu?"}]}'
Response — HTTP 200 (giữ nguyên từ AI server, chuẩn OpenAI)
{
  "choices": [
    {
      "index": 0,
      "message": { "role": "assistant", "content": "Độ ẩm đất của Zone 1 đang là 62%, chưa cần tưới." },
      "finish_reason": "stop"
    }
  ],
  "usage": { ... }
}

Hiển thị choices[0].message.content.

Xác nhận lệnh điều khiển

Khi người dùng yêu cầu điều khiển, trợ lý chưa làm ngay mà hỏi lại. Lúc đó choices[0].message có content là câu hỏi "(Có/Không)" và kèm tool_calls (nội dung do AI server sinh):

{
  "role": "assistant",
  "content": "Bạn xác nhận bật bơm tưới cho ESP32S3_Zone1? (Có/Không)",
  "tool_calls": [ { "id": "call_1", "type": "function", "function": { "name": "...", "arguments": "..." } } ]
}
  1. Thêm nguyên message đó (giữ tool_calls) vào messages[]. App có thể hiện 2 nút Có / Không khi thấy tool_calls.
  2. Thêm câu trả lời của người dùng: {"role":"user","content":"có"} hoặc "không".
  3. Gửi lại toàn bộ messages[]. Trợ lý thực thi hoặc huỷ lệnh.
{
  "messages": [
    { "role": "user", "content": "Tưới nước cho ESP32S3_Zone1 giúp mình" },
    { "role": "assistant", "content": "Bạn xác nhận bật bơm tưới cho ESP32S3_Zone1? (Có/Không)", "tool_calls": [ ... ] },
    { "role": "user", "content": "có" }
  ]
}
Nếu App bỏ tool_calls khỏi lịch sử, câu "có" bị coi là yêu cầu mới và không lệnh nào được thực thi.

Code ESP32 mẫu (PubSubClient)


  

    
    
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <PubSubClient.h>
#include <ArduinoJson.h>

const char* WIFI_SSID     = "<ten-wifi>";
const char* WIFI_PASSWORD = "<mat-khau-wifi>";

const char* MQTT_BROKER   = "ba4fbc53bce842ffb0fcd51178d78414.s1.eu.hivemq.cloud";  // HiveMQ Cloud
const int   MQTT_PORT     = 8883;                // TLS
const char* MQTT_USERNAME = "nod-iot-plant";
const char* MQTT_PASSWORD = "Nod-iot-plant1234";

const char* DEVICE_ID     = "ESP32S3_Zone1";
const char* TOPIC_SENSOR  = "xmini/sensor_data";   // publish telemetry
const char* TOPIC_CONFIG  = "xmini/config";        // publish 15 nguong hien tai
const char* TOPIC_CONTROL = "xmini/control";       // subscribe nhan lenh

WiFiClientSecure wifiClient;                     // TLS bắt buộc cho HiveMQ Cloud
PubSubClient mqtt(wifiClient);

// Nhan lenh: 1 JSON object PHANG, chi cac khoa duoi day (khoa la bo qua)
void onControl(char* topic, byte* payload, unsigned int len) {
  StaticJsonDocument<512> doc;
  if (deserializeJson(doc, payload, len)) return;

  if (doc.containsKey("pump"))      setPump(doc["pump"]);            // ep MANUAL
  if (doc.containsKey("light"))     setLight(doc["light"]);         // ep MANUAL
  if (doc.containsKey("light_pwm")) setLightPwm(doc["light_pwm"]);  // 0-255, ep MANUAL
  if (doc.containsKey("mode"))      setMode(doc["mode"]);           // "auto" | "manual"
  if (doc.containsKey("auto"))      setMode(doc["auto"] ? "auto" : "manual");
  if (doc.containsKey("message"))   showOnTft(doc["message"] | "", doc["message_secs"] | 0);
  if (doc.containsKey("config")) {
    JsonObject cfg = doc["config"].as<JsonObject>();
    if (cfg.size() == 0) publishConfig();          // {"config":{}} = yeu cau gui lai
    else { applyConfig(cfg); saveNvs(); publishConfig(); }
  }
}

void setup() {
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  while (WiFi.status() != WL_CONNECTED) delay(500);

  wifiClient.setInsecure();                        // bỏ verify cert (đủ cho demo)
  mqtt.setServer(MQTT_BROKER, MQTT_PORT);
  mqtt.setCallback(onControl);
  mqtt.setBufferSize(512);
}

void reconnect() {
  while (!mqtt.connected()) {
    if (mqtt.connect(DEVICE_ID, MQTT_USERNAME, MQTT_PASSWORD)) {   // auth HiveMQ Cloud
      mqtt.subscribe(TOPIC_CONTROL, 0);            // QoS 0
      publishConfig();                             // gui 15 nguong hien tai khi ket noi
    } else {
      delay(5000);
    }
  }
}

// Telemetry snake_case PHANG -> xmini/sensor_data
void publishSensor() {
  StaticJsonDocument<384> doc;
  doc["device_id"]        = DEVICE_ID;
  doc["temperature_c"]    = readTemp();
  doc["humidity_percent"] = readHumidity();
  doc["light_lux"]        = readLight();
  doc["soil_percent"]     = readSoilPercent();     // int 0-100
  doc["battery_percent"]  = readBattPercent();
  doc["mode"]             = currentMode();         // "auto" | "manual"
  doc["pump_on"]          = pumpState();
  doc["light_on"]         = lightState();

  char buf[384];
  size_t n = serializeJson(doc, buf);
  mqtt.publish(TOPIC_SENSOR, buf, n);              // QoS 0
}

void loop() {
  if (!mqtt.connected()) reconnect();
  mqtt.loop();

  static unsigned long last = 0;
  if (millis() - last > 10000) {        // ~10s
    publishSensor();
    last = millis();
  }
}

LỗiCách xử lý

    

      AI client không thấy tool
      Check log AI client (Claude Desktop có log ở ~/Library/Logs/Claude/ Mac hoặc %APPDATA%\Claude\logs\ Windows). Thường do đường dẫn Python/server.py sai.
    

    

      ModuleNotFoundError: mcp
      Quên activate venv hoặc pip install -r requirements.txt chưa chạy. Verify lại bằng pytest tests/ -v.
    

    

      Tool gọi nhưng timeout
      Cloudflare Tunnel URL đã đổi — cập nhật config.py với URL mới và restart AI client.
    

    

      "Connection refused" trong log
      Server Mac chưa chạy hoặc tunnel chưa start. Verify: curl https://<tunnel-url>/api/devices phải trả về [].
    

    

      AI không hiểu yêu cầu, không gọi tool
      Đổi model có khả năng tool-calling tốt hơn: Claude (best), GPT-4, llama3.1:70b, qwen2.5:32b. Model nhỏ <7B thường gọi tool kém.

      Dùng double backslash \\ hoặc forward slash / trong path JSON.
