Giới thiệu

Plant Tree IoT là hệ thống quản lý vườn cây thông minh dùng ESP32 + .NET + MongoDB. Server tự động đánh giá rule (độ ẩm, ánh sáng) và sinh lệnh điều khiển (tưới nước, bật đèn) gửi xuống ESP32.

ESP32

MQTT / HTTP
Thu thập sensor (nhiệt độ, độ ẩm, ánh sáng, áp suất), nhận lệnh điều khiển

.NET 10 API

port 8080
REST API + MQTT background service, eval rule engine

MongoDB

port 27017

Vì sao MCP không cần expose ra ngoài

MCP protocol mặc định dùng stdio — Ollama UI spawn MCP server làm subprocess, giao tiếp qua stdin/stdout. MCP server bên trong gọi REST API qua HTTPS tunnel. Đây là cách chuẩn MCP, không cần expose port riêng cho MCP.

Chức năng

Devices

  • Đăng ký thiết bị mới với metadata (tên cây, vị trí, plant type)
  • Heartbeat tracking — server biết device nào online
  • List, search device

Sensor Data

  • Upload telemetry (temperature, humidity, soil moisture, light, pressure, altitude, relay state)
  • Hỗ trợ cả 2 format payload: camelCase (soilMoisture) và snake_case (soil_moisture_percent) — accommodate IoT team firmware hiện tại
  • Lấy sensor mới nhất, history, theo khoảng thời gian

Rules Engine (tự động)

  • Moisture rule: tự sinh command WATER_ON khi soil < min, WATER_OFF khi > max
  • Light rule: tự sinh command LIGHT_ON khi lux < min, LIGHT_OFF khi > max
  • Cooldown chống spam command
  • Server tự động eval rule mỗi lần ESP32 upload sensor — không cần ESP32 hỏi

Control

  • Gửi lệnh thủ công (WATER_ON/OFF, LIGHT_ON/OFF, FAN_ON/OFF)
  • Pending command queue cho ESP32 polling
  • Báo executed để clear queue

Setup mỗi lần chạy

Cảnh báo: Quick Tunnel = URL random, đổi mỗi lần restart cloudflared. Tất cả 4 process đều chạy foreground — đóng terminal là chết.

Thứ tự khởi động (Mac, sau mỗi lần reboot)

1. Mở Docker Desktop

open -a Docker
# Đợi 20–30s, icon cá voi menubar đứng yên

2. Start MongoDB container

docker start mongodb
docker ps    # verify đang Up
# Broker MQTT là HiveMQ Cloud (managed) — không cần start gì cho MQTT

3. Chạy .NET API (Terminal 1 — giữ mở)

cd ~/plant-tree-iot/PlantTreeIoTServer
dotnet run
# Đợi log:
#   "Connected to MQTT broker: ba4fbc53bce842ffb0fcd51178d78414.s1.eu.hivemq.cloud:8883"
#   "Now listening on: http://[::]:8000"

4. Chạy Cloudflare Tunnel (Terminal 2 — giữ mở)

cloudflared tunnel --url http://localhost:8080
# Copy URL "https://xxx-xxx-xxx.trycloudflare.com" từ output
# URL này MỚI mỗi lần chạy — cập nhật mọi nơi dùng

5. Test (Terminal 3)

curl http://localhost:8080/api/devices
# Phải trả về []

curl https://<new-tunnel-url>/api/devices
# Phải trả về [] (test public)

Sync code mới (sau khi sửa server)

# Dừng dotnet (Ctrl+C trong terminal 1)
cd ~/plant-tree-iot
git pull
cd PlantTreeIoTServer
dotnet run

Kịch bản demo

Phần A — IoT team gọi HTTP (5 phút)

Mở Postman / Terminal trên máy Windows, lần lượt:

  1. Đăng ký device ESP32S3_Zone1
  2. Gửi sensor data bằng payload snake_case (giống IoT team đang dùng)
  3. Tạo light rule cố tình trigger (min=500 > current 420.5)
  4. Gửi lại sensor data → response trả về triggeredCommands: [LIGHT_ON]
  5. ESP32 polling /api/control/commands/ESP32S3_Zone1 → lấy lệnh

→ Chứng minh: API public, accept payload IoT team, rule engine real-time.

Phần B — Ollama gọi MCP (5 phút)

Trong Ollama UI đã config MCP server, hỏi tự nhiên:

>>> Liệt kê tất cả thiết bị IoT đang có
>>> Cây ESP32S3_Zone1 hiện tại có cần tưới không?
>>> Tưới cây esp32-001 trong 10 giây
>>> Đặt rule tự động tưới khi độ ẩm < 25%
>>> Cho tôi xem 10 lần đo cảm biến gần nhất

→ Chứng minh: AI tự gọi đúng tool MCP, response từ data thật.

Full demo flow — copy paste sequence

export API=https://<tunnel-url>.trycloudflare.com
export DEVICE=ESP32S3_Zone1

# 1. Đăng ký device
curl -X POST $API/api/devices/register -H "Content-Type: application/json" \
  -d '{"deviceId":"ESP32S3_Zone1","name":"Zone 1","plantType":"Mixed","location":"IoT lab"}'

# 2. Sensor data lần 1 — chưa rule, triggeredCommands rỗng
curl -X POST $API/api/sensordata/upload -H "Content-Type: application/json" \
  -d '{"device_id":"ESP32S3_Zone1","temperature_c":28.4,"light_lux":420.5,"soil_moisture_percent":61.8}'

# 3. Tạo light rule cố tình trigger (min=500 > 420.5)
curl -X POST $API/api/rules/light -H "Content-Type: application/json" \
  -d '{"deviceId":"ESP32S3_Zone1","name":"Demo bat den","minLight":500,"maxLight":600,"isEnabled":true,"cooldownMs":60000}'

# 4. Gửi lại sensor → triggeredCommands có LIGHT_ON
curl -X POST $API/api/sensordata/upload -H "Content-Type: application/json" \
  -d '{"device_id":"ESP32S3_Zone1","temperature_c":28.4,"light_lux":420.5,"soil_moisture_percent":61.8}'

# 5. ESP32 polling lấy lệnh
curl $API/api/control/commands/$DEVICE

Code ESP32 mẫu (PubSubClient)


  

    
    
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <PubSubClient.h>
#include <ArduinoJson.h>

const char* WIFI_SSID     = "<ten-wifi>";
const char* WIFI_PASSWORD = "<mat-khau-wifi>";

const char* MQTT_BROKER   = "ba4fbc53bce842ffb0fcd51178d78414.s1.eu.hivemq.cloud";  // HiveMQ Cloud
const int   MQTT_PORT     = 8883;                // TLS
const char* MQTT_USERNAME = "nod-iot-plant";
const char* MQTT_PASSWORD = "Nod-iot-plant1234";

const char* DEVICE_ID     = "ESP32S3_Zone1";

WiFiClientSecure wifiClient;                     // TLS bắt buộc cho HiveMQ Cloud
PubSubClient mqtt(wifiClient);

char sensorTopic[64];
char commandTopic[64];

void onCommand(char* topic, byte* payload, unsigned int len) {
  String msg;
  for (unsigned int i = 0; i < len; i++) msg += (char)payload[i];

  StaticJsonDocument<512> doc;
  deserializeJson(doc, msg);

  String command = doc["command"];   // WATER_ON / WATER_OFF / LIGHT_ON / ...
  if (command == "WATER_ON") {
    int duration = doc["parameters"]["duration"] | 5000;
    digitalWrite(PUMP_PIN, HIGH);
    delay(duration);
    digitalWrite(PUMP_PIN, LOW);
  } else if (command == "LIGHT_ON") {
    digitalWrite(LIGHT_PIN, HIGH);
  } // ...
}

void setup() {
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  while (WiFi.status() != WL_CONNECTED) delay(500);

  snprintf(sensorTopic,  sizeof(sensorTopic),  "planttree/%s/sensors", DEVICE_ID);
  snprintf(commandTopic, sizeof(commandTopic), "planttree/%s/commands", DEVICE_ID);

  wifiClient.setInsecure();                        // bỏ verify cert (đủ cho demo)
  mqtt.setServer(MQTT_BROKER, MQTT_PORT);
  mqtt.setCallback(onCommand);
  mqtt.setBufferSize(512);
}

void reconnect() {
  while (!mqtt.connected()) {
    if (mqtt.connect(DEVICE_ID, MQTT_USERNAME, MQTT_PASSWORD)) {   // auth HiveMQ Cloud
      mqtt.subscribe(commandTopic);
    } else {
      delay(5000);
    }
  }
}

void publishSensor() {
  StaticJsonDocument<256> doc;
  doc["temperature"]  = readTemp();
  doc["soilMoisture"] = readSoil();
  doc["lightLevel"]   = readLight();

  char buf[256];
  size_t n = serializeJson(doc, buf);
  mqtt.publish(sensorTopic, buf, n);
}

void loop() {
  if (!mqtt.connected()) reconnect();
  mqtt.loop();

  static unsigned long last = 0;
  if (millis() - last > 30000) {        // 30s
    publishSensor();
    last = millis();
  }
}

MCP Tools — Ollama gọi như thế nào


  
MCP tools là thin wrapper trên REST API. Khi AI gọi list_devices(), MCP server làm GET /api/devices và return JSON nguyên vẹn cho AI. Vì vậy response shape giống hệt các endpoint HTTP ở trên.


  

    Chuẩn MCP: Tool được gọi qua stdio (JSON-RPC over stdin/stdout). AI không gọi HTTP trực tiếp — nó gọi tool theo tên, MCP server chuyển thành HTTP request, parse JSON, trả về AI dưới dạng tool result.
  


  
Flow chi tiết

  

    
┌──────┐    1. Tool call    ┌────────────┐    2. HTTP     ┌─────────┐
│ AI   │ ─────────────────► │ MCP server │ ──────────────► │ .NET API│
│Ollama│   list_devices()   │ (Python)   │  GET /api/...   │  :8080  │
└──────┘                    └────────────┘                 └─────────┘
   ▲                              │                              │
   │     4. Tool result           │   3. JSON response           │
   └──────────────────────────────┴──────────────────────────────┘

    Demo argument cho leader: AI không cần code đặc biệt nào để biết cây cần tưới hay không — AI gọi tool, server trả data thật, AI dùng reasoning để phân tích. Đây là chuẩn MCP (Model Context Protocol) — cùng cơ chế Claude Desktop / ChatGPT đang dùng với plugins.
  






  
Setup MCP cho IoT team


  

    Cách MCP hoạt động: MCP server không phải một service public — nó là một process Python chạy local, được AI client (Claude Desktop / Ollama UI / Msty / Open WebUI) tự spawn qua stdio khi cần. Vì vậy IoT team phải cài MCP server trên chính máy chạy AI client, rồi MCP gọi REST API qua Cloudflare Tunnel.

Troubleshooting MCP setup

  

    
LỗiCách xử lý

    

      AI client không thấy tool
      Check log AI client (Claude Desktop có log ở ~/Library/Logs/Claude/ Mac hoặc %APPDATA%\Claude\logs\ Windows). Thường do đường dẫn Python/server.py sai.
    

    

      ModuleNotFoundError: mcp
      Quên activate venv hoặc pip install -r requirements.txt chưa chạy. Verify lại bằng pytest tests/ -v.
    

    

      Tool gọi nhưng timeout
      Cloudflare Tunnel URL đã đổi — cập nhật config.py với URL mới và restart AI client.
    

    

      "Connection refused" trong log
      Server Mac chưa chạy hoặc tunnel chưa start. Verify: curl https://<tunnel-url>/api/devices phải trả về [].
    

    

      AI không hiểu yêu cầu, không gọi tool
      Đổi model có khả năng tool-calling tốt hơn: Claude (best), GPT-4, llama3.1:70b, qwen2.5:32b. Model nhỏ <7B thường gọi tool kém.
    

    

      Windows: lỗi backslash trong config JSON
      Dùng double backslash \\ hoặc forward slash / trong path JSON.

Troubleshooting


  

    
LỗiCách xử lý

    

      Tunnel URL đổi sát giờ demo
      Cập nhật URL trong mcp-server/config.py, gửi IoT team URL mới
    

    

      cloudflared bị Cloudflare throttle
      Ctrl+C dừng, chạy lại cloudflared tunnel --url http://localhost:8080 → URL mới
    

    

      Wi-Fi Mac mất kết nối
      Demo offline LAN, dùng http://localhost:8080 thay vì tunnel
    

    

      MongoDB container crash
      docker restart mongodb
    

    

      dotnet run báo port 8000 đang dùng
      lsof -i :8000 xem process; kill hoặc đổi port trong launchSettings.json
    

    

      Ollama không thấy tool MCP
      Check log MCP, verify config.py URL đúng, test curl tới URL từ máy Ollama
    

    

      "DeviceId is required" khi POST upload
      Code chưa rebuild — Ctrl+C dotnet, git pull, dotnet run lại
    

    

      docker: command not found sau reboot
      Mở Docker.app từ Applications, đợi cá voi menubar đứng yên
    

    

      docker-credential-desktop not found
      echo 'export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
